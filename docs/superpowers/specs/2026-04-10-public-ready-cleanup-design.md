# Public-Ready Cleanup — Design Spec

**Goal:** Get the Claub repo into a state suitable for public visibility on the user's GitHub profile. Not productized for others to deploy — presented so it looks good when recruiters browse it.

**Approach:** Moderate polish. Clean up presentation, remove personal/legacy artifacts, add missing standard files, showcase the prompt engineering and MCP servers.

---

## 1. Deletions

### 1a. `scripts/` directory — remove entirely

All 6 tracked files:
- `ctl.sh`, `run.sh`, `playwright-mcp.sh` — legacy pre-Docker launchd service management
- `com.asempruch.claub.plist`, `com.asempruch.playwright-mcp.plist` — personal identifiers, hardcoded paths
- `clear_discord_commands.py`, `migrate_schedules.py`, `test_webhooks.py` — one-off utilities

These are legacy artifacts from before the Docker migration. They contain personal identifiers (`com.asempruch.*`) and hardcoded paths (`/Users/you/`). No longer relevant to the project's current architecture.

### 1b. `docs/superpowers/` — remove entirely

14 plan/spec files generated by the brainstorming/planning skill during development. These are session artifacts, not project documentation. Remove the entire `docs/superpowers/` directory.

**Note:** This spec itself lives here. Commit it before deleting the directory, or write it elsewhere. The implementation plan should account for this.

### 1c. `handoff-google-oauth.md` — remove

Internal handoff document with hardcoded `/Users/you/` paths. Not relevant to the public repo.

### 1d. `docs/leetcode-api-knowledge-transfer.md` — remove

Documents the LeetCode MCP's API integration, but the MCP itself (with its code and tests) will be in the repo. The code is self-documenting; this separate doc adds clutter.

### 1e. `docs/sandbox-investigation/` — keep, scrub paths

This documents a genuine engineering decision (Docker isolation vs macOS Seatbelt sandbox). Shows thoughtful security analysis — exactly the kind of thing that looks good in a portfolio. Scrub any `/Users/you/` references to generic paths.

## 4. MCP Servers — Move Into Repo

Move three MCP servers from the instance directory into the repo at `mcps/`.

### Which to include

| MCP | Include | Reason |
|-----|---------|--------|
| **git** | Yes | Security-conscious path validation, 15 tools, 202 LOC |
| **leetcode-stats** | Yes | Async/GraphQL, tests, 547 LOC total |
| **nextcloud** | Yes | WebDAV protocol, background cleanup, 321 LOC |
| **google** | No | Thin API wrapper, contains OAuth tokens |
| **latex-resume** | No | Too simple (71 LOC, 1 tool) |

### Repo structure

```
mcps/
  git/
    pyproject.toml
    server.py
  leetcode-stats/
    pyproject.toml
    server.py
    tests/
  nextcloud/
    pyproject.toml
    server.py
```

### Changes needed

- **leetcode-stats**: Remove hardcoded `DEFAULT_USERNAME = "asempruch"` — make it an env var or remove the default entirely.
- **All**: Verify no personal data in any file.

### Dockerfile changes

Add one `COPY` line:
```dockerfile
COPY mcps/ /app/mcps/
```

### Entrypoint changes

Sync both baked-in and instance MCPs:
```bash
# Sync baked-in MCPs
for dir in /app/mcps/*/; do
  if [ -f "$dir/pyproject.toml" ]; then
    cd "$dir" && uv sync 2>&1 | tail -1
  fi
done

# Sync instance MCPs (existing behavior)
for dir in "$CLAUB_HOME/mcps"/*/; do
  ...
done
```

### MCP config

The example `mcp.json` should reference `/app/mcps/` for baked-in servers. Instance MCPs still reference `/claub/mcps/`. The CLAUDE.md documentation should explain both paths.
